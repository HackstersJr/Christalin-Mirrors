1 · Project overview

Christalin Mirrors is a premium salon operating across branches (Bengaluru, and now Gulbarga/Kalaburagi). The project is a complete digital platform with two faces:

  • Customer-facing website — brand presence, services, gallery, and online appointment booking.
  • Staff admin panel — a full salon-management system: point-of-sale billing with GST, appointments, clients, invoices, staff, attendance, inventory, and revenue reporting, all scoped per branch with role-based access.

A backend service and database (Express + Prisma + PostgreSQL) have been built to power both, with authentication, role permissions, and image hosting.

Status in one line: the platform's features are built and demonstrable, but the app currently runs on in-browser demo data and is not yet connected to the live backend/database. This document plans a safe, phased path from "inauguration" to "fully live".

5 · Backend & data platform

A production-oriented backend is already built and awaiting connection:

  • Stack: Express + Prisma ORM + PostgreSQL; JWT authentication; role-based access control (RBAC) middleware; request validation; Cloudinary image uploads.
  • Data models: Branch, Service, Staff, User, Client, Appointment, Invoice, InvoiceItem, ServiceVisit, InventoryItem, SalonSettings, ContactSubmission, and an InvoiceSequence (for unique bill numbers).
  • Services/endpoints present for: auth, clients, staff, services, appointments, invoices, inventory, settings, branches, and dashboard aggregation.

Remaining work to make it live

  • Provision & host the PostgreSQL database; run migrations & seed reference data (branches, services, staff, owner/manager/receptionist users).
  • Deploy the backend API (with HTTPS) and set environment secrets (DB URL, JWT secret, Cloudinary keys).
  • Point the frontend to the live API and replace the mock login & in-browser store with real API calls.
  • Data backup & restore routine.

8 · Rollout plan (phased)

Phase 0 — Inauguration & soft launch  31 Jul 2026

  • Publish the customer website (brand, services, branches, gallery) — safe, read-only for visitors.
  • Run the admin panel in demo mode on the reception desk for showcasing & staff familiarisation.
  • Take real bookings/bills on the existing manual process (or single-desk app) — see §10 fallback.

Goal: a confident public launch without depending on unfinished data plumbing.

Phase 1 — Controlled pilot (single desk)  Week 1

  • Connect authentication + billing + appointments + clients to the live backend for one reception station at Gulbarga.
  • Receptionist uses it for real transactions while the manual method runs in parallel as backup.
  • Daily check that bills, GST, and totals reconcile.

Phase 2 — Full backend cutover  Weeks 2–3

  • All admin modules read/write the live database; retire the in-browser store and mock login.
  • Seed real services, staff, and users; enable backups.
  • Multiple devices at the branch share the same data. Retire the manual parallel run once stable.

Phase 3 — Payments & convenience  Weeks 3–5

  • Integrate Pine Labs card terminals (per the separate Pine Labs plan) — auto-mark invoices paid.
  • Ship bill auto-archive to folder (receptionist) for easy reprints.

Phase 4 — Scale & optimise  Week 6+

  • Roll the same live setup to Bengaluru; enable full multi-branch reporting for the owner.
  • Optional: thermal receipts, automatic WhatsApp confirmations, loyalty, deeper analytics.

9.2 · Priority test scenarios (billing)

  • Walk-in: register client → add 2 services + 1 product → 10% discount → GST → cash with change → print → WhatsApp.
  • Appointment → bill: pull items from today's appointment → pay by UPI → mark appointment completed.
  • GST correctness: verify CGST + SGST each = half of GST and sum exactly to total on odd amounts.
  • Reschedule: change an appointment's date & time; verify it updates everywhere.
  • Cross-branch client: a Bengaluru client billed at Gulbarga is found and linked.

10 · Inauguration-day plan & fallback (31 Jul)

On the day

  • Customer website live and checked on phone & desktop.
  • Reception laptop/desktop set up with the admin panel; owner & receptionist logins tested.
  • Admin panel used to showcase billing, appointments, and dashboards to guests/staff.
  • WhatsApp bill sharing demonstrated.
  • Staff walkthrough / mini-training on the POS flow.
Because central data isn't connected yet, treat the software on day one as a demo + single-desk tool, not the shared system of record. Keep the existing manual billing/receipt method available for actual transactions until Phase 2 completes.

Fallback for real transactions (until Phase 2)

  • Take payments as today (cash/UPI/existing card machine) and issue a manual/printed receipt.
  • If using the app on the single reception desk, do not clear the browser cache, and export/print bills at day-end.
  • Record the day's bills so they can be entered once the live database is ready (optional).

12 · Go-live checklist

Before go-live (Phase 2 cutover)

  • Database provisioned, migrated, seeded (branches, services, staff, users).
  • Backend deployed over HTTPS with secrets set; health-checked.
  • Frontend pointed to live API; mock login & in-browser store removed.
  • Real owner / manager / receptionist accounts created & tested.
  • Invoice numbering verified unique & sequential.
  • GST rate & invoice format confirmed with accountant.
  • Backup routine enabled & a restore tested.
  • All §9 test phases passed; staff UAT signed off.
  • Support contact & rollback plan agreed.

13 · Post-launch support & roadmap

  • Hypercare (first 2 weeks): daily reconciliation, fast bug fixes, on-call support during business hours.
  • Then: Pine Labs payments, bill auto-archive, Bengaluru cutover, all-branch reporting.
  • Future options: automatic WhatsApp appointment confirmations/reminders, loyalty & offers, thermal receipt printing, client GSTIN on invoices, deeper analytics, and staff performance dashboards.
Bottom line: inaugurate confidently on 31 July with the website live and the admin panel as a showcase/single-desk tool; then execute Phases 1–2 quickly to make it the shared, backed-up system of record, followed by payments and convenience features.
